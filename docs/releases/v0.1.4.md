# public-wt v0.1.4

**Released:** 2026-11-02 · **Commit:** `a06c448` · **Previous:** [v0.1.3](v0.1.3.md)

## What it does

Cycle-level stall profile of any gfx1100 kernel (hipcc, Mojo, hand asm) from a real SQTT thread trace
on the 7900 XTX, through tinygrad's KFD runtime. Shows, per instruction, how many cycles each wave
waited before it issued.

```
                    run_hsaco.py                       wavewait (Mojo)
k.hsaco ──► tinygrad custom kernel ──► sqtt-capture ──► profile.pkl ──► per-pc table
           (ELF swapped in, hidden     (SQTT,                       (llvm-objdump pc map,
            kernargs filled)            WGP 3 pinned)                  waves walked by packet)
```

## Highlights

- A walk that loses the code now fails instead of printing plausible, wrong causes.
- Dispatches with no code object id get the right kernel, not the next free one.
- The walk is about twice as fast.

## Changes

### Added
- `--allow-mism` shows the numbers of a desynced walk, with a warning.
- `tools/doctor.sh`: what this machine needs to capture, with the fix.
- `tools/perf-receipt.sh`: wall time and peak RSS per run.
### Changed
- A walk with mismatches exits 3 on the table, `diff`, `budget` and `app`.
- `check.sh` keeps a sha receipt and skips a tree it already passed.
- The walk uses flat per-pc and per-wave arrays. On a 33 MB trace run, `app` is about 53 % faster, compounded from three same-session medians.
### Fixed
- A code.json with rows and no object id: wavewait matches the rows, then keeps the objects whose walk stays aligned. Several fits print `(1ofN)`.
- `check.sh` no longer leaks temp dirs.

## Known limits

- `(1ofN)`: wavewait cannot tell which of N matching objects ran; the name shows the first.
- The audit of a torch matmul still flags 2 `s_waitcnt` rows: AMD and wavewait split cycles differently after `ds_store`. Totals agree within 0.12 %.
- SQTT cold runs mislead: trace a warm dispatch.
- One GPU reset came during a ComfyUI server preflight, cause not proven.
