# wavewait v0.1.0

**Released:** 2026-10-22 · **Commit:** tag `v0.1.0` · **Previous:** first release

## What it does

Cycle-level stall profile of any gfx1100 kernel (hipcc, Mojo, hand asm) from a real SQTT thread trace
on the 7900 XTX, through tinygrad's KFD runtime. Shows, per instruction, how many cycles each wave
waited before it issued.

```
                    run_hsaco.py                       wavewait (Mojo)
k.hsaco ──► tinygrad custom kernel ──► sqtt-capture ──► profile.pkl ──► per-pc table
           (ELF swapped in, hidden     (SQTT,                       (llvm-objdump pc map,
            kernargs filled)            WGP 3 pinned)                  waves walked by packet)
```

## Highlights

- Per-instruction stall table for any gfx1100 kernel (hipcc, Mojo, hand asm) from a real SQTT thread trace: cycles each wave waited before issue, with a cause per row.
- `diff`, `--json`, `--by-line` (DWARF), `--hints`, `app` mode over a rocprofv3 ATT run, `budget` CI gate, and a self-contained `--html` wave timeline.
- `tools/sqtt-capture` finds the 7900 XTX by PCI id and drives tinygrad's KFD runtime (`TINYGRAD` = your checkout).

## Known limits

- gfx1100 (7900 XTX) only. Capture needs a patched tinygrad (`wgp-probe.patch`) and root to fix clocks.
- CU mode only under capture: build with `-mcumode`, a WGP-mode workgroup never launches.
- One kernel per code object, pointer args only (filled with 1.0f), 1-D grid.
- `wavewait sim` is blocked on a per-SIMD scheduler model and exits 2.
- No emulator replay: tinygrad's emulator does not decode `buffer_gl0_inv`.

## Upgrade / run

```
./check.sh                                         # CPU gate, no GPU needed
mojo build -I src src/wavewait.mojo -o build/wavewait
TINYGRAD=/path/to/tinygrad tools/sqtt-capture $PWD/tools/run_hsaco.py OUTDIR   # see README "Use"
build/wavewait OUTDIR/profile_run_hsaco.pkl --causes --top 10
```
